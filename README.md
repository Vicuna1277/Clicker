# Clicker

Android 点击、手势与脚本录制工具，支持 ROOT 和 Shizuku 

支持以脚本名称供其他第三方应用静默调用，详情请查看[接口说明](SCRIPT_API.md)。。


## 功能

- **主页**：查看输入后端、请求授权，设置连点次数与间隔，打开连点悬浮窗。
- **普通脚本**：编辑点击、延时、滑动、循环和随机点击指令，配置执行次数、间隔与速度。
- **录制脚本**：读取物理触摸事件，记录点击与滑动并回放；支持在录制脚本中插入普通指令。
- **自定义脚本**：管理组合动作流程。
- **自定义悬浮窗**：配置悬浮快捷按钮及其绑定操作。
- **应用调用授权**：维护允许调用接口的包名列表，按包名排序，设置自动保存。

界面使用 Jetpack Compose / Material 3，支持系统明暗主题；Android 12 及以上默认使用系统动态配色。

当前界面不提供脚本 JSON 导入、导出和创建桌面快捷方式。内部仍使用 JSON 保存脚本，已有脚本无需转换；此前创建的桌面快捷方式不会自动删除。

## 输入后端

| 后端 | 当前实现 |
| --- | --- |
| ROOT | 优先使用内置原生 uinput，其次尝试系统 uinput，最后使用 shell input 兼容后端 |
| Shizuku | ROOT 不可用时，通过 UserService 注入单指触摸事件，支持点击、长按、滑动及已有轨迹回放 |
| Shizuku 录制 | 试用功能：通过 UserService 直接读取物理触摸设备，是否可用取决于设备权限 |

打开主页时自动尝试 ROOT 授权；ROOT 管理器仍可能要求用户确认。Shizuku 需要另行安装、启动并在主页授权，不会自动弹出授权请求。授权后可点击输入模块的“开启”初始化输入。

默认优先 ROOT；测试 Shizuku 时，应在 ROOT 不可用的情况下确认当前后端显示 `SHIZUKU`。已经就绪的后端不会在每条指令间切换。

Shizuku 的 ADB 权限与 ROOT 不同，不能保证所有设备都允许读取 `/dev/input`。权限拒绝、设备不可见或录制事件流中断时，应用会提示失败。依赖前台应用检测的功能也需要实际验证，Shizuku 路径没有自动授予使用情况访问权限。

## 开始使用

1. 在主页完成 ROOT 或 Shizuku 授权，确认输入后端已就绪。
2. 允许 Clicker 显示在其他应用上层；按系统要求允许通知。
3. 在“功能”页创建普通脚本、录制脚本或组合流程。
4. 从脚本列表进入执行页，配置参数并打开运行悬浮窗，再返回目标应用运行。
5. 如需其他应用调用，在“授权”页添加调用应用的真实包名，并阅读[接口说明](SCRIPT_API.md)。

脚本会操作当前屏幕，不负责判断目标应用的业务状态。首次使用请先运行短脚本确认坐标、按住时长与等待时间。

## 使用边界

- 主要面向主屏单指操作；尚未适配多指、外接显示器和跨设备坐标自动换算。
- 录制的是触点坐标与手势时长，不完整复现手指接触面积、压力或目标应用的按钮状态。
- 录制时改变屏幕方向、分辨率或界面布局，可能影响回放；固定使用环境后再录制。
- ROOT 的 shell input 兼容后端会将复杂轨迹退化，优先使用原生 uinput 或 Shizuku 后端。
- Shizuku 录制及最新录制收尾调整仍需设备验证，不能保证完全不丢事件。
- 接口执行时显示前台通知和 Clicker 自己的 8dp 蓝色状态点；没有悬浮窗权限时跳过状态点并记录日志，不自动打开设置。
- 部分厂商仍可能冻结后台进程。通知和状态点不等于后台运行保证；必要时允许 Clicker 后台运行。
- 停止后，已开始的手势通常先完成抬起；不保证系统强杀、断电或 Shizuku 进程突然结束时仍能清理。

## 本地构建

使用 Android Studio 打开本目录，配置 Android SDK / NDK / CMake 后同步项目。构建配置如下：

| 项目 | 配置 |
| --- | --- |
| Android Gradle Plugin | 8.1.4 |
| Gradle Wrapper | 8.2 |
| Kotlin | 1.9.22 |
| JDK | 17 |
| compileSdk / targetSdk | 34 / 33 |
| minSdk | 24 |
| 原生 ABI | arm64-v8a |

`minSdk=24` 是当前配置值，不代表已完成 Android 7 及以上的兼容验证；部分窗口代码使用 Android 11 及以上 API。当前只打包 arm64 原生库。

`local.properties` 应指向本机 SDK。`app/build.gradle` 中 debug / release 共用现有签名配置，其他开发者应使用自己的签名文件，并通过 `KEYSTORE_FILE`、`KEY_ALIAS`、`KEYSTORE_PASSWORD`、`KEY_PASSWORD` 环境变量配置，或自行调整签名配置；默认路径依赖原开发机。不要提交私有签名文件及密码。

构建、打包与设备验证由开发者在本地进行，文档不代表当前提交已通过完整构建或兼容测试。

## 排查问题

Logcat 可按以下标签筛选：

- `ClickerTrace`：调用请求、指令进度、前台服务、状态点、取消及结果。
- `ScriptApi`：接口执行异常。
- `RootInput`：输入后端与手势执行错误。
- `RootTouchRecorder`：录制错误，以及手势首末坐标、点数与时长。
- `ShizukuInput`：Shizuku 连接、注入及录制通道错误。

注：后台调用出问题，大部分原因都出手机后台冻结了Clicker，把后台权限放开基本没问题。
